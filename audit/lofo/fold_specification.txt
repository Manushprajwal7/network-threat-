MODEL / METHOD CONFIGURATION (fixed across all folds — not tuned per fold)

Isolation Forest hyperparameters (read from the currently saved
saved_models/isolation_forest.pkl via .get_params(), matching
evaluate_unknown_threats.get_isolation_forest()'s construction call):
  n_estimators   = 200
  contamination  = 0.05
  random_state   = 42
  n_jobs         = -1
  bootstrap      = False
  max_features   = 1.0
  max_samples    = 'auto'
  warm_start     = False
These are identical for all 7 folds. Each fold's Isolation Forest is a freshly
fit sklearn.ensemble.IsolationForest instance trained ONLY on that fold's
training set (family excluded), using the identical hyperparameters above.

Anomaly decision rule / "threshold":
  evaluate_unknown_threats.py does NOT define a separate numeric anomaly-score
  cutoff. It classifies via `if_pred = iforest.predict(X_test_scaled)`
  (line 461), which uses scikit-learn's internal decision boundary (the
  fitted `offset_` attribute) established automatically during `.fit()` from
  contamination=0.05. There is no independent "threshold" value to hold fixed
  beyond contamination itself. Per fold, each Isolation Forest computes its
  own `offset_` as a direct, deterministic consequence of fitting with the
  same contamination=0.05 on that fold's own training data — this is REQUIRED
  for LOFO to be meaningful (the model must be trained on data that excludes
  the held-out family) and is NOT the same thing as retuning a threshold
  per fold. No manual threshold search or adjustment is performed anywhere.
  (Note: an unrelated constant ANOMALY_THRESHOLD = 0.55 exists in
  unknown_attack_detector.py, but that belongs to a different, differently-
  normalized scoring path used only by the live/production detect_unknown()
  function — it is not used by evaluate_unknown_threats.py and is not used
  here.)

XGBoost classifier (fixed, not retrained per fold):
  Model path: backend/ml_model/saved_models/xgboost.pkl
  Trained on the FULL original training set (all 34 classes), unmodified.
  Used identically across all 7 folds to compute per-flow confidence
  (max predict_proba) on each fold's test-unknown and test-known sets.
  Confidence threshold: CONFIDENCE_THRESHOLD = 0.60
    (evaluate_unknown_threats.py, line 82)

Hybrid fusion rule (OR-fusion, read verbatim from evaluate_unknown_threats.py
line 477 — not invented):
    pred_unknown = (confidence < CONFIDENCE_THRESHOLD) | (if_pred == -1)
  i.e. a flow is flagged "unknown" if EITHER XGBoost's top-class confidence
  is below 0.60 OR the fold's Isolation Forest flags it as anomalous
  (if_pred == -1). Applied identically in every fold.

Feature preprocessing asymmetry (preserved per fold, per instruction):
  - XGBoost confidence is computed on CLIPPED, UNSCALED features
    (fold's X_test slice from audit/lofo/cache/X_test.npy — same clip
    bounds as used for the original full-dataset preprocessing, since
    XGBoost was trained on data clipped that same way).
  - Isolation Forest is trained and scored on CLIPPED, SCALED features
    (fold's X_train_scaled / X_test_scaled slices from
    audit/lofo/cache/X_train_scaled.npy / X_test_scaled.npy).
  - clip_lower.pkl, clip_upper.pkl, scaler.pkl, label_encoder.pkl,
    feature_columns.pkl are NOT refit per fold. The cached arrays already
    embed the ONE clip+scale transformation fit on the full original
    training set (backend/ml_model/saved_models/{scaler,clip_lower,
    clip_upper,label_encoder,feature_columns}.pkl, unmodified, verified
    byte-identical to the git-committed versions via `git diff --exit-code`
    after this dataset-recovery work). Per-fold train/test arrays are pure
    boolean-mask slices of these same base arrays — no re-fitting occurs.
